# R7 — интервал PR на оцифрованных листах

Решение — SD-110, критерий записан до правок. Ядро не менялось.

- **Файлы.** Набор подбора — [tune_cases.jsonl](tune_cases.jsonl); приёмочный набор на новом коде —
  [standard_m3_cases.jsonl](standard_m3_cases.jsonl); ecgdig 9 × 40 до правок —
  [ecgdig_pr_base.jsonl](ecgdig_pr_base.jsonl), после — [ecgdig_pr_after.jsonl](ecgdig_pr_after.jsonl).

## Что было не так

Стенд считал ошибку PR, но «плохим» лист делали только RR, QRS и QT. Лист с верными RR, QRS, QT и
неверным PR получал «ok». На `standard_m3` таких было 3 (ошибка 29–45 мс). От PR зависят заключения:
АВ-блокада I степени, короткий PR.

## Что изменено

1. **PR входит в определение «плохого» листа стенда.** Список интервалов — `acceptance.bad_intervals`
   в `bench.yaml`.
2. **Предупреждение PR_UNSTABLE** (`validate.pr_min_onset_ratio: 0.5`). Ядро измерило PR, но начало
   зубца P уточнило меньше чем у половины комплексов и взяло PR по запасным началам P. Такое чтение
   не «ok». Код в контракте; тексты RU/UZ на сервере и в приложении.

Правило выбрано на отдельном наборе подбора (114 новых листов, начальное число 20261113): там оно
поймало 2 из 2 листов с неверным PR без пометки и пометило 3 из 53 верных «ok»-листов.

**Пробовали и отбросили:**

- Расхождение двух оценок PR ядра (D250). Вторая оценка на листах 3×4 почти не получается: 2 листа из
  75 в наборе подбора, на ecgdig ни одного.
- Разброс PR между комплексами. У верно прочитанных «ok»-листов он доходит до 55 мс, а у части
  неверных — около 4 мс.

## Критерий SD-110

| Требование | Результат |
|---|---|
| 1. PR в определении «плохого» листа, список в настройке | ✅ |
| 2. `standard_m3`: плохих без пометки 0 (было 3) | ✅ 0 |
| 3. Из 56 верных «ok»-листов остаются «ok» не меньше 51 | ✅ 52: потеряны clean_scan-005, gain_5-002, layout_6x2-002, ptbxl_photo-001 |
| 4. ecgdig: PR показан без пометок и неверен — не выше исходного ни в одном варианте, ниже в сумме | ✅ v1 5 → 4, v2 5 → 5, v8 4 → 3; всего 14 → 12 |
| 5. ecgdig: ЧСС, QRS, пометки ядра и путь чтения не меняются | ✅ совпали на всех 360 листах (PR тоже) |
| 6. Код в контракте, тексты RU/UZ, порог в настройке, тесты | ✅ |
| 7. Знак расхождения двух оценок PR | ➖ неприменим: способ с двумя оценками отброшен |

`standard_m3`: ok 52 / на подтверждение 61 / отказ 1 (было 59 / 54 / 1).

## ecgdig (только проверка)

- Флаг встал на 6 листах: 1334-v1, 1454-v1, 1218-v1, 1455-v1, 1454-v2, 1218-v8.
- Из них PR неверен на двух (1334-v1: 170 мс при 197; 1218-v8: 184 при 144). На четырёх PR верен:
  это ложные пометки.
- 1218-v8 был «на подтверждение» и до правки (BEATS_INCONSISTENT из той же проверки измерением);
  остальные пять были «ok».

## Не решено

- **12 чтений ecgdig с неверным PR без пометки ядра и без PR_UNSTABLE**, 9 из них со статусом «ok»
  (v1 — 4, v2 — 3, v8 — 2). Ошибка 21–97 мс; худшие — записи 1246 (184–237 мс при 270) и 1651
  (115 и 168 мс при 212). У них начало P уточнено у большинства комплексов, так что правило их не
  видит. Разброс PR на них большой (34–81 мс у 8 из 9), но на наборе подбора разброс верные листы от
  неверных не отделял.
- **Эталон PR на ecgdig — тоже измерение ядра** по исходному сигналу, и у части записей он сам
  неустойчив (разброс до 50 мс). Часть «ошибок» может быть ошибкой эталона.
- **Флаг проверяется только на чтениях, дошедших до проверки измерением со статусом «ok».** Чтение,
  которое уже «на подтверждение» по другой причине, отдельной пометки PR не получает (например
  1108-v8, 1334-v2: PR по запасным началам P, пометки PR нет).

## После объединения с ядром (D263)

Ядро теперь учитывает флаг: на листе с PR_UNSTABLE оно не выдаёт АВ-блокаду I степени и «пограничный
PR» и добавляет пометку «PR ориентировочно» (`pr_approximate`). Проверка R7 повторена на объединённом
коде (b1358ca), строки — [ecgdig_pr_merged.jsonl](ecgdig_pr_merged.jsonl).

- **ecgdig:** ЧСС, QRS, PR, пометки ядра, путь, статус и предупреждения сканера совпали с прогоном до
  объединения на всех 360 листах.
- **Пометка `pr_approximate` стоит на тех же 6 листах, что и флаг, и больше нигде.** Остальные
  заключения на них те же, что с выключенным флагом (сверено повторным чтением шести листов).
- **Ни одно заключение по PR на ecgdig не скрыто:** на этих шести листах его не было и без флага.
  В том числе на 1455-v1 (PR 266 мс при эталонных 248) АВ-блокада I степени не выдаётся ни с флагом,
  ни без него — вопрос передан ядру.
- **`standard_m3`:** статусы и ошибки интервалов совпали на всех 114 листах; плохих без пометки 0.
