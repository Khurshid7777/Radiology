# Точки расширения P2 (ТЗ 18.11, SD-097)

ТЗ 18.11: консультация, архив пациента с серийным сравнением, QR-код, подпись врача — **не
реализовывать сейчас, только заложить точки расширения**. Сделаны поля контракта, интерфейсы,
формат QR и выключатели. Пользователь ничего нового не видит.

## Выключатели

`configs/scanner/service.yaml` → `extensions`: `consult`, `archive`, `qr`, `signature`, все `false`.

- Приложение спрашивает `GET /scans/config/features` и показывает функцию, только если она
  включена. Сервер без этого запроса для приложения значит «всё выключено».
- Включить функцию без зарегистрированной реализации нельзя: сервис не запустится и назовёт, чего
  не хватает. Функция либо есть целиком, либо её нет.
- Неизвестный ключ в `extensions` — тоже ошибка запуска.

## Что заложено

| Функция ТЗ 18.11 | Контракт | Интерфейс (`ecgscan_service/extensions.py`) |
|---|---|---|
| Консультация: ссылка коллеге, комментарий на отведении, уведомления | `LeadRef`: канал выгрузки (`I`…`V6`, `II_rhythm`) и отрезок времени на её оси | `ShareLinks`, `Comments`, `Notifier` |
| Архив пациента и сравнение с прошлой ЭКГ | `ScanResult.subject_ref`: выданный клиникой псевдоним `sub_…` | `SubjectArchive`: `previous_analysis` даёт ядру `prior_ecg_id` (серийное сравнение ядра уже есть) |
| QR: привязка к пациенту, вход в веб-версию | формат `cv1:s/<subject_ref>`, `cv1:l/<одноразовый токен>`, `ecgscan/qr.py` | — |
| Подпись врача | `Confirmation.signature` (ed25519, `key_id`, хеш, подпись); `ScanResult.content_sha256()` — что подписывается | `Signer` |

## Правила для будущей реализации

- **Пациент только по псевдониму.**
  - `subject_ref` — это `sub_` и от 8 до 64 знаков (латиница, цифры, `_`, `-`).
  - ФИО, дата рождения, голый номер карты по формату не проходят ни в контракте, ни в QR.
  - Псевдоним выдаёт система клиники, сканер его не придумывает.
- **Ссылка коллеге:**
  - случайный токен со сроком жизни, ведёт на один снимок, может быть отозвана;
  - каждое открытие пишется в журнал снимка;
  - без явного действия врача ничего не отправляется (ТЗ 18.12).
- **Комментарии:**
  - лежат вместе со снимком и удаляются вместе с ним;
  - без имён, тот же предел длины, что у комментария подтверждения.
- **Уведомление** несёт только номер снимка.
- **QR-код:**
  - читается только в формате `cv1:`; любой другой текст, в том числе адрес сайта, отклоняется;
  - код входа одноразовый и короткоживущий.
- **Подпись:**
  - подписывается `content_sha256()`: канонический JSON результата (ключи по порядку, без
    пробелов, UTF-8) без самой подписи;
  - любое изменение сигнала, калибровки, статуса или подтверждения меняет хеш;
  - ключ врача не покидает `Signer`.
