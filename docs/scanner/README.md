# ECG Scanner (модуль Cardiolens)

Входной адаптер модальности «фото/скан» для CardioLens. Он превращает фото
бумажной ЭКГ с телефона или планшета в калиброванный сигнал (мВ, секунды) по
каждому отведению, с оценкой достоверности, и честно отказывает, если качество
низкое. Это не диагностика: модуль только оцифровывает.

> Инструмент поддержки принятия решений. Не заменяет врача. Не медицинское изделие.

## Главное

- Подложка (SD-065): напечатать `python -m ecgscan board --name a3 --out board_a3.pdf` в масштабе
  100 %, положить ЭКГ в рамку, снимать сверху так, чтобы все 8 меток были в кадре, и отправлять
  файлом. Сканер сам находит подложку, выпрямляет зону и проверяет разрешение; без подложки
  работает прежний путь по сетке. Если целиком не хватает разрешения, лист снимают двумя-тремя
  частями (в каждой видно ≥ 3 меток) и отправляют одним заданием — части склеиваются по меткам (SD-066).
  Нет принтера A3: `--name a3x2` печатает ту же подложку на двух листах A4 (лист 1 отрезать по
  пунктиру и положить на лист 2), в зону входит лист A4 альбомом (SD-076). Подложка A4 — только для
  узких лент. Масштаб ЭКГ берётся по сетке бумаги, подложка даёт плоскость: неровная печать офисного
  принтера (1–3 мм по ходу бумаги) на время не влияет (SD-075). Бумага с тоном или цветной сеткой
  может лежать и поверх линеек: читается всё до меток, на A4-подложке до 248 × 161 мм (SD-077).

- CardioLens уже умеет оцифровывать страницу 3×4 + ритм и ленту 12×1 (D35–D72).
  Сканер строится поверх этого кода (SD-003), а не заново.
- Цель «≤ 10 мс» относится к ошибке, которую вносит оцифровка (SD-010).
- Фото, отправленное в Telegram как фото, сжимается примерно до 4 px/мм, а порог
  ТЗ 8 px/мм. Поэтому отправлять нужно файлом (SD-009).
- Базовая линия M1 (SD-022): текущий оцифровщик хорош на чистом скане (r 0.97,
  QT 3 мс), но на фото не проходит ни одного критерия ТЗ, не определяет
  50 мм/с и 20 мм/мВ и в 71 % плохих случаев отвечает «ok». Это и есть план M2–M3.
- Итог M2 (SD-030): на «фото чистой бумаги» выполнены 6 из 8 критериев ТЗ
  (RR 0, QRS 8,5, QT 3 мс, r 0,96, ошибка R 0,03 мВ, 0 % плохих без пометки).
  Не выполнены SNR (10 дБ при пороге 15) и время (14 с при лимите 10 с).
  50 мм/с и 20 мм/мВ теперь определяются; доля плохих без пометки по всему
  набору 71 % → 26 %.
- Лента 3-канального аппарата (SD-059):
  - раскладка «3x4 strip»: 4 группы по ~4 с с промежутками, один импульс в начале ленты;
  - группы называются по положению, поэтому снимок без начала ленты или не со всеми группами
    отклоняется (`PAGE_INCOMPLETE`);
  - по реальным снимкам исправлены пропуск низкоамплитудной строки, разбитые маской трассы и импульс, а
    также «висящий» импульс, который становился лишней строкой.
- Итог M3 (SD-038): собственная сегментация, панели из реестра, векторизация
  (DP + D47, «гибрид»), проверка тождеств конечностных отведений, артефакты
  подтверждения. На «фото чистой бумаги» снова 6 из 8 критериев (RR 0,6, QRS
  5,2, QT 3,5 мс, r 0,95), SNR 10,9 дБ и время 11,9 с ещё не проходят. По всему
  набору r 0,95 (старый оцифровщик 0,39). Плохих без пометки 4 из 114: трассы
  точные, ошибку даёт измерение ударов CardioLens на краю окна отведения (M4).
- Итог M4 (SD-044):
  - API `/scans` (очередь, SQLite, зашифрованные оригиналы, ключи доступа, подтверждение врачом с
    журналом и обратной связью, передача в CardioLens), Telegram-бот, тексты RU/UZ;
  - фото в CardioLens никогда не идёт в автономный режим B и помечено в заключении (D130);
  - плохих без пометки 4 → 2 из 114;
  - CI, красный с M2 из-за совпадения имён тестов, исправлен (SD-043).
- M5 (SD-046…SD-050):
  - Flutter-клиент `mobile/ecg_scanner`: проверка кадра с автозахватом (одна спецификация с
    сервером, паритет на эталонных кадрах), маскирование шапки с проверкой перед отправкой, очередь
    загрузки без сети, экран подтверждения с наложением;
  - обвязка для реальных фото (`--real`, GE MUSE XML).

  Не хватает самих реальных фото с цифровыми оригиналами.
- M6 (SD-051…SD-055):
  - нейросетевой сегментатор: маленький U-Net, 122 тыс. параметров, ONNX на CPU. Учился только на
    синтетике, маска — настоящий штрих пера;
  - на всём наборе он лучше классики: r 0,94 → 0,97, SNR 9,9 → 11,8 дБ, `ok` 46 → 58, плохих без
    пометки 3 → 2. Поэтому включён по умолчанию; классика доступна как `segmentation.kind: classic`;
  - при сравнении исправлены ещё две вещи, для обеих версий: импульс, вложенный в импульс, и скос
    аффинного фото;
  - время скана ускорено до ≤ 10 с (SD-056); крутые фронты QRS читаются по строкам (SD-058): SNR по
    набору 11,8 → 14,0 дБ, на чистой бумаге 14,95 дБ — на пороге 15, формально 7 из 8 критериев;
  - ширина QRS, зависящая от маленькой R′ (БПНПГ), помечается `QRS_UNSTABLE` (SD-057, D131): плохих без
    пометки по всему набору 0 из 114 ([отчёт](../../reports/scanner/m6-final/report.md));
  - как пересобрать: `python tools/scanner/build_segmenter_data.py --out data/segmenter2`, затем
    `python tools/scanner/train_segmenter.py --data data/segmenter2 --channels 8,16,32,64` (нужен
    torch). sha256 из `model_card.json` вписать в `pipeline.yaml`.
