# Бенчмарк сканера ЭКГ (этап M1)

Одна команда строит синтетический набор, прогоняет все доступные оцифровщики и
пишет отчёт по срезам (ТЗ §11):

```bash
pip install -e ".[dev]"
python -m ecgscan bench --suite standard --out reports/scanner/<имя> --cases data/scanner_bench/standard
```

Результат в `reports/scanner/<имя>/`:
- `report.md` — таблицы по срезам и критерии приёмки, по-русски;
- `summary.json` — то же машинно-читаемо;
- `cases.jsonl` — каждая пара «случай × оцифровщик» с метриками по трассам.
  Файл генерируемый, в git не коммитится.

`--cases` переиспользует готовый набор: изображения генерируются один раз, а
следующие оцифровщики сравниваются на тех же картинках. Набор `smoke` (4 случая,
6 px/мм) нужен для быстрой проверки. Отдельные срезы: `--slices photo_clean speed_50`,
отдельные оцифровщики: `--digitizers cardiolens-v0`.

## Что внутри

| Модуль | Назначение |
|---|---|
| `ecgscan.bench.render` | рисует страницу любой раскладки из реестра при любой скорости, усилении и px/мм (дробные px/мм субпиксельно), с шапкой «ФИО/ID» и строкой «25 mm/s 10 mm/mV», калибровочными импульсами, подписями. Истина — точный сигнал за каждой нарисованной трассой |
| `ecgscan.bench.degrade` | дефекты бумаги (мятость, сгибы, пятна, выцветание), съёмки (стол, перспектива, поворот), света (тень, виньетка, блик, темнота), оптики и сенсора (размытие, шум, разрешение, JPEG). Детерминировано по seed, хранит гомографию «страница → фото» |
| `ecgscan.bench.sources` | синтетические пресеты (взрослые и детские, ЧСС до 190) и записи PTB-XL: `fetch_ptbxl_sample` скачивает N записей в `data/ptbxl` (не коммитится) |
| `ecgscan.bench.digitizers` | единый интерфейс: `ecgscan` (этот модуль, сегментатор из `pipeline.yaml`), `ecgscan-classic` (он же с классическим сегментатором, M6), `cardiolens-v0` (текущий оцифровщик вслепую), `cardiolens-v0-oracle` (ему сообщены истинные скорость и усиление), внешние инструменты отдельным процессом |
| `ecgscan.bench.metrics` | r, SNR, RMSE, ошибка R по трассам; RR/QRS/QT/PR — ошибка, вносимая оцифровкой (SD-010); калибровка; «плохие без пометки» |
| `ecgscan.bench.run`, `report` | агрегирование по срезам, критерии приёмки, отчёт |

Срезы, наборы и пороги приёмки — в `configs/scanner/bench.yaml`, раскладки — в
`configs/scanner/layouts/*.yaml`.

## Определения метрик

- **r, SNR, RMSE** — по каждой трассе после поиска сдвига начала времени ±0,25 с.
  Оба сигнала центрируются медианой, потому что абсолютную изолинию на бумаге
  оцифровщик знать не может. В случае берётся медиана по трассам, в срезе —
  медиана по случаям. Пропуски (`null`) в сравнение не входят, они снижают
  покрытие и **не интерполируются**.
- **ΔR** — модуль разницы самого высокого положительного отклонения.
- **RR/QRS/QT/PR** — средняя абсолютная разница измерений делинеатора CardioLens
  (слои 2–3) на истине *в тех же окнах отведений* (то, что отдал бы идеальный
  оцифровщик) и на результате оцифровки. Ошибка самого делинеатора против
  разметки в эту метрику не входит (SD-010).
- **Плохой случай** — ошибка RR, QRS или QT больше 20 мс, либо интервал измерен
  на истине, но не на результате.
- **Плохие без пометки** — плохой случай, вернувшийся со статусом `ok`. По ТЗ эта
  доля должна стремиться к нулю. Отказ (`rejected`), `needs_confirmation` и
  ошибка оцифровщика считаются честными исходами.
- **Скорость/усиление ✓** — заявленное значение совпало с истинным.

## Проверка самого бенчмарка

Прежде чем верить цифрам, бенчмарк сверен с измерениями CardioLens (D43–D64):
страницы и порча из `cardiolens.layer1_ingestion.digitize`
(`render_ecg_page`, `degrade_image(perspective=0.02, vignette=0.4, texture=0.3,
blur_px=1, jpeg_quality=45, rotation_deg=1.5)`) через метрики `ecgscan` дают
r 0.974–0.976 на чистой странице и 0.82 / 0.83 / 0.22 на фото по трём seed.
Это совпадает с README CardioLens («0.76 при 6 px/мм, один seed из трёх 0.44»).
Тесты: `tests/scanner/test_bench.py` (идеальный оцифровщик даёт r = 1 и нулевые
ошибки; «50 мм/с прочитано как 25» даёт половинную ЧСС и считается «плохим без
пометки»; отказ и ошибка честные).

## Внешние базовые линии и данные (SD-012, SD-019)

- **Open-ECG-Digitizer** (CC BY-SA 4.0), **ECGtizer**, **ECGMiner** —
  `configs/scanner/bench.yaml: external`. Подключаются как отдельный процесс,
  который пишет `result.json` в форме ScanResult. Шаблон команды берётся из
  переменной окружения (`OPEN_ECG_DIGITIZER_CMD="python wrapper.py {image}
  {out_dir}"`). Обёртку под формат вывода инструмента пишем, когда он
  установлен. Из этой среды github.com закрыт, поэтому пока они «не
  запускались», и это указано в отчёте.
- **ECG-Image-Kit** (BSD-3) — склонировать его отсюда нельзя (403). Его выход
  (`<запись>-0.png` + WFDB) и ECG-Image-Database подключаются как папка с парами
  «изображение + запись»: это задача M5 вместе с реальными фото.
