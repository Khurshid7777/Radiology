# Сервис сканера и Telegram-бот (M4)

## Запуск API

```bash
pip install -e ".[scanner]"
export ECGSCAN_API_KEYS="bot:<ключ бота>,dr_ivanova:<ключ врача>"     # без ключей API отвечает 503
export ECGSCAN_STORAGE_KEY=$(python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())")
uvicorn cardiolens.api.app:app        # CardioLens + /scans
# или только сканер:  uvicorn ecgscan_service.app:app
```

Ключ хранилища нужно сохранить: без него зашифрованные оригиналы не прочитать. Если ключ не задан,
оригиналы не хранятся вовсе (см. SD-040). Настройки — `configs/scanner/service.yaml`.

## Пример

```bash
curl -H "X-API-Key: $KEY" -F file=@ecg.jpg -F client=api localhost:8000/scans
# {"scan_id": "…", "status": "queued"}
# Лист на подложке, снятый по частям (SD-066): первая часть в file, остальные в parts (до 4 снимков)
curl -H "X-API-Key: $KEY" -F file=@left.jpg -F parts=@right.jpg localhost:8000/scans
curl -H "X-API-Key: $KEY" localhost:8000/scans/<id>            # статус, результат, тексты RU/UZ
curl -H "X-API-Key: $KEY" -H 'Content-Type: application/json' \
     -d '{"decision": "corrected", "paper_speed_mm_s": 50}' localhost:8000/scans/<id>/confirm
curl -H "X-API-Key: $KEY" -X POST localhost:8000/scans/<id>/analysis   # заключение CardioLens
```

### Возможности сервера (P2, SD-097)

`GET /scans/config/features` → `{"features": {"consult": false, "archive": false, "qr": false,
"signature": false}}`. Сейчас все выключены — см. [EXTENSIONS.md](EXTENSIONS.md).

### Выгрузка сигнала (S4, SD-094)

```bash
curl -H "X-API-Key: $KEY" -OJ "localhost:8000/scans/<id>/export?format=wfdb"   # ecg-<id8>.zip: ecg.hea + ecg.dat
curl -H "X-API-Key: $KEY" -OJ "localhost:8000/scans/<id>/export?format=csv"    # time_s и по столбцу на канал
curl -H "X-API-Key: $KEY" -OJ "localhost:8000/scans/<id>/export"               # JSON контракта ScanResult
```

- **Ось одна:** все каналы на общей оси времени с частотой `sampling_rate_hz`, от t = 0.
- **Порядок каналов:** 12 отведений в стандартном порядке, затем полосы ритма (`II_rhythm`).
- **Пропуски:** отведение есть только в своём окне листа (на 3x4 — 2,5 с). Вне окна значение
  пустое (CSV) или недопустимое (WFDB), а не ноль.
- **Точность WFDB:** формат 32 при 100 000 единиц/мВ, то есть шаг 0,01 мкВ, точность самого
  контракта.
- **Без потерь:** CSV и WFDB читаются обратно бит в бит
  (`ecgscan.export.read_csv` / `read_wfdb_zip`).
- **Комментарии WFDB:** статус, скорость и усиление с источником, раскладка и предупреждения.
  Персональных данных нет.
- **Ошибки:**
  - чужой снимок — 404;
  - неизвестный формат — 422;
  - снимок ещё без трасс — 409.
- **Журнал:** каждая выгрузка пишется в журнал действий (`exported`, формат).

## Бот

```bash
pip install -e ".[scanner,bot]"
export ECGSCAN_BOT_TOKEN=<токен от @BotFather>
export ECGSCAN_BOT_API_KEY=<ключ бота из ECGSCAN_API_KEYS>
export ECGSCAN_BOT_ALLOWED=<telegram user_id через запятую>
python -m ecgscan_bot
```

Адрес API и таймауты — `configs/scanner/bot.yaml`. ЭКГ отправляется **файлом** (скрепка → «Файл»).

### Бот в группе (SD-107)

Бот читает фото ЭКГ, которые участники выкладывают в группе, и присылает разбор администраторам в личный
чат. В самой группе он ничего не пишет: ни ответов, ни подсказок, ни реакции на команды.

**Как включить (владелец):**

1. В @BotFather: `/setprivacy` → выбрать бота → **Disable**. Иначе Telegram не показывает боту обычные
   сообщения группы. Вместо этого можно сделать бота администратором группы.
2. Добавить бота в группу. Каждому администратору бота в личный чат придёт сообщение с кнопками
   «Читать фото» / «Не читать». Если сообщение не пришло — администратор пишет в группе `/watch`
   (бот в группе промолчит, кнопки придут в личку).
3. Нажать «Читать фото». Перевыкладка не нужна: список групп хранится на сервере рядом с кодами
   приглашений.

**Что приходит в личку:** строка «Из группы «название»» со ссылкой на сообщение, заключение, наложение
прочитанной кривой, PDF и те же кнопки, что в личном чате (скорость, усиление, симптомы, язык).
Снимок, который анализ не принял, приходит одной строкой с причиной (`group.notify_refusals`).

**Оценка врача (SD-108).** Под разбором — кнопки «✅ Заключение верно» и «❌ Неверно»; после «Неверно»
бот просит написать, что на самом деле (без ФИО). Ответ уходит в журнал обратной связи сервера: id
анализа, согласие, кто оценил, источник. Это материал для разбора ошибок; сама система по нему не
переучивается.

**Команды администратора (только в личном чате):** `/groups` — группы и переключатели; `/admins` —
Telegram id администраторов и получателей разборов; `/report [дней]` — сводка реального использования
(SD-109): сколько ЭКГ пришло, сколько прочитано, под пометкой, не принято и почему, оценки врачей. Та же
сводка приходит сама раз в неделю (`report` в `bot.yaml`).

**Съёмка в полном качестве (SD-137).** `/scan` в личном чате: бот присылает кнопку, которая открывает страницу
`/miniapp/capture` как мини-приложение Telegram. Врач нажимает «Снять ЭКГ» (или выбирает фото из галереи), и снимок уходит
на сервер **как есть, оригиналом**: выбирать «фото или файл» не нужно, Telegram его не сжимает. Сервер сразу проверяет снимок
(те же подсказки, что при съёмке: ближе, блик, свет, тень, куда сдвинуть телефон) и, если замечаний нет, отдаёт его боту;
если есть — показывает их с кнопками «Переснять» и «Отправить как есть». Дальше бот ведёт обычный разбор: вопросы о пациенте,
заключение, PDF, кнопки. Как устроено:
- кнопка несёт одноразовый билет (случайный номер, срок, подпись ключом бота `ECGSCAN_BOT_API_KEY`); id Telegram в нём нет,
  токен Telegram серверу сайта не нужен. Срок — `miniapp.ticket_minutes` в `bot.yaml` (10 минут; сервер не примет билет
  длиннее своего `miniapp.max_ticket_minutes`). Прежние кнопки чата продолжают работать до своего срока; живых кнопок на чат
  не больше `miniapp.max_buttons` (самая старая гаснет);
- когда кнопка отработала, бот убирает её из своего сообщения; когда срок вышел, а снимок не пришёл, пишет в том же сообщении
  «Кнопка больше не действует… отправьте /scan ещё раз» (без нового уведомления): потерянный снимок не остаётся молчаливым;
- `POST /miniapp/upload` и `POST /miniapp/send` открыты, но принимают только живой неиспользованный билет. До чтения тела
  проверяются билет, число загрузок по нему (`miniapp.max_uploads_per_ticket`, дальше 401 — нужна новая кнопка) и объявленный
  размер; тело читается потоком с пределом `upload.max_mb` (413) и обрывается на первых байтах, если это не снимок из
  `upload.mime` (JPEG, PNG, TIFF — по сигнатуре, а не по имени или типу от клиента; 415, страница просит снять камерой);
- снимок ждёт бота **в памяти**, на диск не пишется, по истечении билета стирается; одновременно ждать могут не больше
  `miniapp.max_waiting` снимков (`service.yaml`), дальше 429;
- бот забирает снимок через `GET /scans/miniapp/inbox/<номер>` под ключом клиники (только тем, что подписал билет), один раз;
  сервер после этого его забывает, билет больше не принимается;
- билеты проверяются подписью, сервер их не хранит: после перезапуска сервера живая кнопка продолжает работать (страница
  предложит повторить отправку), а ждавший снимок и список использованных билетов теряются. Перезапуск бота обрывает ожидание:
  врач отправляет `/scan` заново;
- память общая только в одном процессе сервера (так образ и запускается); при нескольких процессах `uvicorn` нужен общий склад;
- адрес страницы с билетом попадает в журнал доступа сервера (Telegram заменяет часть адреса после `#` своими данными,
  поэтому билет в строке запроса); билет одноразовый, живёт до 10 минут и не содержит данных пациента или врача.
- лист снят боком (SD-138): проверка кадра смотрит на углы листа (`FrameQC.sideways`: вертикальная сторона листа ≥
  `thresholds.sideways_ratio` × горизонтальная; лист не найден — вертикален ли сам снимок, как в проверке ядра D171), и ответ
  загрузки несёт `turn: true`. Страница тогда показывает две уменьшенные копии снимка — повёрнутую против часовой и по часовой —
  и «Оставить как есть»; врач одним касанием выбирает ту, где строки идут слева направо и подписи не вверх ногами. Сторону
  по картинке угадать нельзя (перевёрнутый лист читается с зеркальным QRS), поэтому сервер сам не поворачивает. Выбор уходит
  в `POST /miniapp/send?rotate=0|90|180|270` (иное — 422); поворот делает сервер при выдаче боту: декодирование с учётом
  EXIF, четверть оборота, JPEG с качеством `miniapp.turn_jpeg_quality` (95). Без поворота бот получает байты оригинала;
- обе страницы отвечают и на `HEAD`; в рамке их может показать только Telegram Web (`frame-ancestors https://web.telegram.org`),
  ему же, и только ему, страницы шлют события готовности через `postMessage`.
Фото, PDF и файлы аппарата по-прежнему можно присылать в чат.

**Несколько снимков одной записи (SD-147).** Длинную ленту снимают частями: на странице съёмки «Добавить ещё снимок» (камера)
и «Ещё из галереи» (можно выбрать несколько сразу) добавляют снимки по порядку, до `miniapp.max_files` (10) и
`miniapp.max_total_mb` (60 МБ) на запись; список показывает каждый снимок с его подсказками («лист уходит за край» при съёмке
частями не показывается); «Убрать последний» убирает снимок, «Отправить (N)» отдаёт все боту, и он разбирает их как одну
запись, по порядку (как альбом в чате). Отправка всегда по кнопке: прежней автоотправки одного снимка нет. Поворот (SD-138)
спрашивается и делается для каждого снимка свой. Бот забирает снимки одним ответом: части подряд, размеры в `X-Miniapp-Sizes`.
Весь склад — не больше `miniapp.max_store_mb` (300 МБ), дальше 429.

**Команды и ссылка на съёмку (SD-146).** При запуске бот выставляет список команд личных чатов (`/scan`, `/app`, `/probe`, RU и
UZ) — настраивать их в BotFather не нужно. Ссылка `https://t.me/<имя бота>?start=scan` открывает личный чат и сразу присылает
кнопку съёмки (допущенным; остальным — обычный отказ с подсказкой про код); её можно разослать врачам.

**Сжатое фото → кнопка «Переснять в полном качестве» (SD-144).** Если в личный чат пришло фото «как фото» (сжатая копия),
предупреждение бота несёт ту же кнопку страницы съёмки, что и `/scan`: одно касание — и снимок уйдёт оригиналом; сжатая копия
при этом разбирается как раньше. По истечении срока у предупреждения убирается только кнопка, текст остаётся.

**Сайт в Telegram (SD-142, D349 ядра).** `/app` в личном чате допущенного: кнопка «Открыть CardioVision» открывает корень
сайта (`<публичный адрес>/`) как мини-приложение; ключ клиники сайт спрашивает сам, как в браузере, — в адресе нет ни ключа,
ни билета, ни id. Та же кнопка ставится этому чату как кнопка меню (слева от поля ввода) при `/start` и `/app`. При отзыве кода
кнопка меню не снимается: без ключа клиники сайт ничего не показывает.

**Замер камеры (SD-134, SD-136).** `/probe` в личном чате (любой допущенный пользователь): бот присылает кнопку,
которая открывает страницу `/miniapp/probe` как мини-приложение Telegram. Страница показывает только числа: что даёт
живая камера, снимок камерой телефона и фото из галереи внутри Telegram на этом телефоне. Она ничего не отправляет
(сетевого кода нет, а заголовки ответа запрещают браузеру любые соединения); отчёт врач копирует и присылает сам.
Маршрут открытый (у Telegram нет ключа клиники) и статический; нужен публичный адрес сайта `https://`
(`ECGSCAN_BOT_PUBLIC_URL` или `public_url` в `service.yaml`).

**Настройки:** `ECGSCAN_BOT_GROUP_RECIPIENTS` — кому из администраторов слать разборы из групп (по
умолчанию всем из `ECGSCAN_BOT_ALLOWED`; id вне этого списка отбрасывается). `ECGSCAN_BOT_GROUPS` —
группы, включённые без кнопки. `group.max_per_hour` в `bot.yaml` — не больше стольких разборов в час на
группу.

**Данные пациентов.** Фото из группы идёт тем же путём, что фото из личного чата: в `/api/analyze`, с
теми же сроками хранения на сервере. Бот держит файлы только в памяти (15 минут, для кнопок пересчёта).
Подпись к фото используется только для возраста, пола, скорости и симптомов; сам текст подписи никуда
не пересылается. Участников группы стоит предупредить, что бот читает выложенные ЭКГ.
Язык ответа: узбекский для клиентов Telegram на узбекском, иначе русский.

## Тексты

Все тексты статусов, кодов отказа и предупреждений, а также бота лежат в
`configs/scanner/i18n/{ru,uz}.json`. Узбекские тексты (латиница) нужно проверить с носителем языка.

## Сводка качества и метки врача (SD-130)

`python tools/scanner/quality_report.py --db <scans.db> --feedback <feedback.jsonl> [--out report.json] [--labels labels.jsonl]`

Читает базу сервиса и журнал решений врача только на чтение. В сводке числа: доли статусов, причины отказов, предупреждения на
прочитанных, чем установлены скорость и усиление, найденные раскладки, масштаб (10 / 50 / 90-й перцентиль px/мм), решения врача,
какие поля врач менял и как часто сканер угадал раскладку. Идентификаторов снимков, хешей, комментариев, имён и ключей в выходе
нет (тест `tests/scanner/test_quality_report.py` проверяет это на заполненной базе). `--labels` пишет метки врача: поле, значение
сканера, значение врача, статус и коды предупреждений сканера, для будущей проверки на реальных снимках.
