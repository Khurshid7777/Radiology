# Состояние проекта ЭКГ (CardioLens + ECG Scanner)

Короткая точка входа для человека и для новой сессии Claude. Подробности — в
[README](../README.md), [DECISIONS.md](../DECISIONS.md) (решения `D###`) и
[docs/scanner/DECISIONS.md](scanner/DECISIONS.md) (решения `SD-###`).

Обновлено: 2026-10-26, код до D163 и SD-073.

## Что это

Одна система из двух частей в одном репозитории:

| Часть | Код | Что делает |
|---|---|---|
| **CardioLens** | `src/cardiolens/` | Конвейер интерпретации ЭКГ: приём (WFDB, EDF, CSV, DICOM, SCP-ECG, фото 3×4 и ленты 12×1) → предобработка → измерения → находки → safety → каузальный граф → заключение RU/UZ (LLM или офлайн). FastAPI + веб-UI, Telegram-бот, приём от аппарата по DICOM. |
| **ECG Scanner** | `src/ecgscan/`, `src/ecgscan_service/`, `src/ecgscan_bot/`, `mobile/ecg_scanner/`, `tools/scanner/`, `models/segmenter/` | Входной адаптер «фото/скан → калиброванный сигнал» с оценкой качества и честным отказом. Подложка с метками ArUco, съёмка частями, ONNX-сегментатор, Flutter-клиент. Сам не ставит диагноз — отдаёт сигнал в CardioLens. |

Связка: бот читает фото сначала сканером, на отказах по раскладке — читалками CardioLens (D139);
результат сканера с сомнительным масштабом не принимается на веру (D144).

## Правила совместной работы

1. В `main` и в основную ветку пишет только главная сессия. Сканер отдаёт работу коммитом в своей
   ветке и сообщает об этом главной сессии.
2. Номера решений: ядро — `D###` (ведёт главная сессия), сканер — `SD-###`. Правка ядра из ветки
   сканера получает номер `D###` при вливании.
3. Любое изменение правил находок: критерий записывается в DECISIONS **до** прогона; отложенная
   проверка — PTB-XL fold 10, один прогон; не прошло — откат.
4. Перед вливанием: `ruff check src tests` и `pytest -q` зелёные, тесты на фото не меняются без
   объяснения.
5. После значимого шага обновлять этот файл: раздел «Сейчас в работе» и «Ждём от владельца».
