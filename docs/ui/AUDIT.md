## 2. Данные результата (`POST /api/analyze`, JSON)

| Вопрос ТЗ | Ответ по коду |
|---|---|
| Заключение | `conclusion_ru`, `conclusion_uz` — готовый текст (с дисклеймером); `interpretation` — структурно (summary, differential, red_flags, confidence, next_step, reasoning_trace, disclaimer RU/UZ). |
| Измерения | `measurements`: ЧСС, ритм, интервалы `intervals` (PR, QRS, QT, QTc ×3), оси `axes`, вольтажи, морфология, ~40 полей. |
| **Нормы** | **В ответе нет.** Нормы живут на сервере (`configs/norms/*.yaml`, по возрасту и полу) и в ответ не попадают. → Шкал с нормой в MetricCard без изменения бэкенда не будет (ТЗ запрещает хардкод — согласен). |
| **Кривая** | **Только картинка**: `GET /api/analysis/{id}/waveform.svg` (рисует сервер, отведения находки подсвечены, D196). Массива отсчётов в ответе нет (есть только `r_peaks_samples`). → EcgViewer с прорисовкой, перекрестием и линейкой невозможен без нового эндпоинта; без него — масштаб/панорама SVG. |
| **Причинный граф** | **И картинка, и данные**: `graph.png` + `causal_graph.nodes[]`, `edges[]`, `activated_rules`, `critical_flags` в JSON. → интерактивный граф и «показать списком» возможны без бэкенда. |
| Находки | `findings[]`: code, label_ru/uz, group, critical, confidence, evidence (в т. ч. отведения — D196). |
| Предупреждения | `critical_alerts[]`, баннер режима, `speed_note_ru`, `device_ru`, находки группы `quality` (`photo_coarse`, `photo_unreliable`, `no_ecg_signal`…), `symptom_advice[]`. |
| Уверенность чтения трасс | `overlay_available` + `GET …/overlay.jpg` — **цвета зелёный/оранжевый/красный нарисованы сервером на картинке**, отдельных значений уверенности по отведениям в ответе нет. |
| **Стадии анализа** | **Нет.** Запрос синхронный (ответ целиком, 2–20 с, фото дольше). Потоковых стадий нет. → только неопределённый индикатор + текст (как и требует ТЗ). |
| PDF | `GET …/report.pdf`; ссылка коллеге `POST …/share` → `/s/{token}` (D197). |

## 4. Текущий вид и находки

1. **Горизонтальный скролл на 360 px (дефект).** Ширина документа 477 px: значок `#llm` в шапке
   («Текст заключения: офлайн-шаблон · анализ: правила + обученная модель», `white-space:nowrap`) не помещается.
2. **«Текст заключения: …» в шапке — не заглушка.** Это значок «кто пишет текст» (языковая модель или
   офлайн-шаблон), заполняется из `/health` после загрузки; «…» — состояние до ответа. Длинный текст на мобильном
   — см. п. 1.
3. **Ожидание**: кнопка бледнеет, под ней «Отправляю… N с». Нет `aria-live` (на странице 0 атрибутов `aria-live`),
   нет индикатора на самом снимке.
4. **Ошибка**: красный текст под кнопкой, тоже без `aria-live`; текст отказа — от сервера (с советом).
5. **Результат на мобильном** — под всей формой (~1 300 px прокрутки), первым идёт баннер режима, затем
   заключение `<pre>`, PDF, ссылка, «Что прочитано с фото» (оверлей), «Подробно» свёрнуто (измерения, симптомы,
   сравнение, находки, кривая, граф, UZ, ход рассуждений). Иерархия «главное → подробности» уже частично есть.
6. **Форма** уже частично соответствует ТЗ: возраст и пол обязательны и видны; калий, кальций, режим, частота/единицы
   CSV, демо-случай, ключ клиники, «Качество за 30 дней» — **свёрнуты** в «Дополнительно». **Режим A/B свёрнут**
   (ТЗ требует видимым).
7. **Инструкция съёмки** — абзац текста под зоной загрузки (ТЗ R7 актуален).
8. **Локализация интерфейса RU/UZ уже есть** (D200, переключатель в шапке, словарь в странице; узбекский текст
   — черновой, ждёт вычитки носителем).
9. **Анимаций нет** (ни `transition`, ни `@keyframes`, ни `prefers-reduced-motion`).
10. Тёмная тема по системной настройке уже есть — ТЗ её не упоминает (см. конфликт К5).
11. Есть функции, которых нет в списке ТЗ 6.3 «сохранить»: симптомы и время начала, сравнение с прошлой ЭКГ,
    история анализов в браузере, ссылка коллеге, панель поворота снимка, блок качества, обратная связь врача
    (`/feedback`). **Сохраняю все.**

## Фаза 2 — сделано (P2)

Скриншоты — `docs/ui/p2/` (ожидание, «Результат», «Лаборатория» на 360 / 768 / 1280), Lighthouse — там же.
Проверка в браузере: `node tools/ui/check_p2.js <адрес> <ключ>` (демо-случай, 1280 px и 360 px с
`reduced-motion`), 20 из 20: значения ключевых показателей в DOM **равны ответу API**; результат показан
≤ 400 мс после ответа; все предупреждения (находки группы «качество», принятая скорость ленты, аппарат), критические
тревоги и дисклеймер — в первом слое; «Лаборатория» скрыта до нажатия; «Новый пациент» очищает; ошибок в консоли
нет; горизонтального скролла нет. Статические проверки — `tests/test_page_ui.py`.

- **Ожидание:** «стадии» по таймеру удалены (бэкенд их не отдаёт). Неопределённый индикатор — полоса-сканер
  поверх миниатюры снимка (только из памяти страницы, `URL.createObjectURL`, освобождается после анализа),
  затемнение navy 60 % с сеткой; статус `aria-live`: «Анализирую снимок…» / «…запись…», через 10 с — «Это
  занимает дольше обычного…». По готовности — последний проход ≤ 350 мс поверх уже показанного результата,
  касанием пропускается; при `reduced-motion` полосы нет.
- **Слой 1 «Результат»:** баннер режима, критические тревоги, предупреждения, 5 ключевых значений (ЧСС, PR, QRS,
  QTc Bazett, ось — ровно числа API; у ненадёжного снимка — только освобождённая ЧСС D189), заключение с
  переключателем RU / UZ, PDF, ссылка коллеге, «Переснять» / «Новый пациент», прочитанные трассы с
  предупреждением, дисклеймер.
- **Слой 2 «Лаборатория»** (тёмный navy): таблица измерений, подсказка по симптомам, сравнение, находки, кривая,
  граф, заключение на втором языке, ход рассуждений. Переход — «шторка» `clip-path` 350 мс от кнопки, при
  `reduced-motion` — мгновенно. Вкладки — `role=tab`, стрелки ← →.
- **«Переснять»** — убирает файл и результат, оставляет пациента и показывает это явной строкой на шаге 1;
  **«Новый пациент»** — очищает возраст, пол, симптомы, сравнение, калий/кальций, скорость/усиление, CSV.
  Ключ клиники, язык и режим остаются.
- PDF: предупреждения о снимке и строка «поддержка решений врача» в нём есть (проверено на сжатом снимке
  4 px/мм) — бэкенд не менялся.
- Пока картинка кривой (~270 КБ) грузится — заготовка «миллиметровка» вместо значка битой картинки.

Lighthouse mobile: 100 / 100 / 96 / 90, LCP 1,4 с, CLS 0, TBT 0. Рост страницы с начала работ: +5,8 КБ gzip
(бюджет ТЗ +30 КБ).

**Отклонения Фазы 2 от ТЗ:** миниатюра под сканером — только для изображений; для PDF / файла записи /
